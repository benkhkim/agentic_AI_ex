# agentic_AI_ex

Agentic AI와 워크플로: 글쓰기 UI로 보는 차이
1. Agentic AI란

Agentic AI는 사람이 정한 목표를 받아, 그 목표를 이루기 위한 단계와 도구 사용을 AI가 스스로 정하고 실행하는 인공지능 시스템이다.

일반 챗봇이 "질문 하나에 답 하나"로 끝나는 반면, Agentic AI는 다음 과정을 목표가 달성될 때까지 반복한다.

계획: 목표를 보고 무엇부터 할지 정한다.
행동: 검색, 문서 작성, 파일 저장 같은 도구를 골라 실행한다.
관찰: 도구가 돌려준 결과를 확인한다.
판단: 결과에 따라 다음 행동을 정한다. 계속할지, 고칠지, 멈출지, 사람에게 물을지.

핵심은 "어떻게 할지"를 사람이나 코드가 아니라 AI가 정한다는 점이다.

구성 요소
요소	역할	글쓰기 예시
목표	무엇을 이룰지	"의료 AI 주제로 A4 한 장 글 완성"
모델	판단하고 계획하는 두뇌	Claude
도구	실제로 일을 하는 수단	글 저장·검증, 개념 추가, 근거 요청
관찰	행동 결과를 다시 읽기	검증 결과 "8개 중 6개 통과"
지식·기준	판단의 근거	온톨로지(개념·관계·용어·근거)
워크플로와의 구분
워크플로(Workflow): 단계와 순서를 사람이 미리 코드로 정해 둔 시스템. AI는 각 단계 안에서 내용만 만든다.
에이전트(Agent): 단계와 순서, 도구 사용을 AI가 실행 중에 정하는 시스템.

둘은 딱 나뉘기보다 스펙트럼에 가깝다. 정해진 순서 안에 "결과를 보고 고쳐 쓰는 고리"가 있으면 워크플로에 agentic 요소가 들어간 형태다.

2. 두 가지 글쓰기 UI 소개

두 방식 모두 같은 페이지(Agentic AI를 사용한 '의료 AI' 주제 글쓰기)에서 「작업 방식」을 바꿔 쓸 수 있다. 공통으로 왼쪽에는 온톨로지 편집기, 오른쪽에는 글쓰기 설정과 A4 원고 화면이 있다.

2-1. 워크플로 방식 글쓰기 UI

화면 위에 5단계 진행 표시줄이 있고, 버튼을 누르면 정해진 순서대로 진행된다.

주제·온톨로지 선택
개념 조회: 온톨로지의 개념·관계·근거를 읽는다.
개요 설계: 관계를 따라 문단 순서를 정하고 개요를 보여 준다.
초안 작성: 개요대로 서론·본론·결론을 쓴다.
검증: 필수 개념, 피할 표현, 근거 없는 수치, 분량, 구성을 점검한다.

검증에서 문제가 나오면 정확히 한 번 4단계로 돌아가 고쳐 쓴 뒤 끝난다. 사용자는 진행 표시줄로 지금 몇 단계인지 본다.

2-2. 에이전트 방식 글쓰기 UI

진행 표시줄 대신 에이전트 활동 기록이 나타난다. 「에이전트에게 맡기기」를 누르면 Claude가 목표와 도구 3가지를 받고, 언제 무엇을 쓸지 스스로 정한다.

글 저장·검증: 글을 저장하면 검증 결과가 Claude에게 돌아간다. 다시 고칠지, 그대로 둘지 Claude가 판단한다(최대 3회).
개념 추가 제안: 글에 필요한데 온톨로지에 없는 개념을 왼쪽 표에 추가한다. 저장 여부는 사람이 정한다.
근거 요청: 필요한 수치가 근거 목록에 없으면 지어내지 않고 사용자에게 요청한다.

활동 기록에는 Claude가 한 일이 순서대로 남고, 마지막에 왜 그렇게 판단했는지 보고가 붙는다.

3. 차이점
구분	워크플로 방식	에이전트 방식
단계 순서	코드에 고정 (5단계)	Claude가 실행 중에 결정
도구 선택	정해진 호출만	3가지 도구 중 Claude가 골라 씀
고쳐 쓰기	문제가 있으면 정확히 1회	필요하다고 판단할 때, 최대 3회
근거가 부족할 때	수치 없이 쓰고 검증에서 표시	사용자에게 근거를 요청
온톨로지 보완	하지 않음	필요한 개념을 스스로 제안
화면	5단계 진행 표시줄, 개요	활동 기록, 마무리 보고
결과의 일관성	높음 (매번 같은 과정)	실행마다 과정이 달라질 수 있음
비용·시간	예측 가능	판단에 따라 늘어날 수 있음
사람의 역할	순서를 설계하고 결과 확인	목표와 기준을 주고 판단을 검토
어느 쪽을 쓰면 좋은가
워크플로: 여러 사람이 같은 양식과 품질로 글을 반복해서 써야 할 때. 과정이 예측 가능해야 할 때.
에이전트: 주제마다 필요한 근거나 개념이 달라 상황 판단이 필요할 때. 온톨로지를 함께 키워 가고 싶을 때.

두 방식 모두 온톨로지가 판단의 기준 역할을 한다. 온톨로지가 충실할수록 워크플로는 더 정확해지고, 에이전트는 더 좋은 판단을 내린다.

4. 요약
Agentic AI는 목표를 받아 계획 → 행동 → 관찰 → 판단을 스스로 반복하는 AI다.
워크플로는 사람이 정한 순서를 따르고, 에이전트는 AI가 순서를 정한다.
같은 글쓰기 페이지 안에서 두 방식을 바꿔 가며 쓰면 차이를 직접 확인할 수 있다.

5. 단점
첫째. 오류가 쌓인 결과를 받을 수 있습니다. 
에이전트는 여러 단계를 연달아 실행합니다. 앞 단계에서 작은 실수를 하면 그 결과를 믿고 다음 단계를 진행하므로, 끝에 가면 오류가 커져 있을 수 있습니다. 챗봇의 오답은 사람이 읽고 걸러내지만, 에이전트의 오류는 이미 파일 저장이나 메일 발송 같은 행동으로 이어진 뒤일 수 있습니다.
둘째. 비용과 시간이 늘 수 있습니다.
AI가 판단을 여러 번 하고 도구를 여러 번 부르면 그만큼 사용량과 시간이 듭니다. 단순한 일에 에이전트를 쓰면 번거롭고 비쌉니다. 실제로 기업의 솔루션은 거대언어모델의 토큰처럼 사용량으로 과금을 합니다. 그게 클라우드 방식이건 온프레미스 방식이건 결국 비용을 지불해야 합니다.
셋째. 사람의 검토 부담이 사라지지 않습니다. 
"알아서 해 준다"고 해도 결과를 확인하는 일은 남습니다. 오히려 AI가 무엇을 왜 했는지까지 따라가며 검토해야 해서, 결과만 보면 되던 때보다 일이 늘기도 합니다. 
넷째. 보안 위험이 커집니다.
에이전트에 메일, 파일, 결제 같은 권한을 주면 사고의 범위도 커집니다. 특히 웹페이지나 문서 속에 숨겨진 지시문을 AI가 명령으로 착각해 따르는 프롬프트 인젝션이 대표적인 위험입니다. 개인정보나 사내 기밀이 외부 도구로 흘러갈 가능성도 따져 봐야 합니다.****
